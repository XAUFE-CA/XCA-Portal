# 首页入场

Status: adopted

本文描述首页场景、启动输出与终端归位的协作。命令和会话接口见 [终端扩展接口](terminal-extending.md)，导航、主题与共享玻璃样式接入见 [站点框架](site-shell.md)。文档职责独立，源码仍由首页组件与终端 presentation 共同承担。

## 启动与会话

每次完整加载首页都会播放入场，客户端路由返回保留会话并跳过自动重播。`xca intro` 重播前复用 `Session.resetWelcome` 恢复初始输出，保留命令历史、身份、目录和外观。重播、跳过和展开共用唯一的真实 TerminalHost，不创建替代终端或第二份会话。

首页画布与入场遮罩复用同一份背景底色及渐变定义，渐变按视口定位，首帧、CA 绘制和终端交接保持背景连续。场景雾化读取首页已解析的画布底色，沿用深浅色与系统配色的现有解析结果。

减少动画偏好下自动跳过空间入场，主动重播仍展示可读的启动消息与 ASCII，省略位移和缩放。文字阅读节奏独立于空间动画时长。`public/intro-gate.js` 在首帧前设置首页入场状态，避免正常布局提前闪现。入场状态仅在首页设置。

首页标题从 `app/data/hero-sentences.json` 读取双语轮播内容。终端交互开始后，标题完成当前文字单元再暂停并隐藏光标。点击终端外部恢复，不能仅靠 mouseleave 恢复。

## 场景绘制

`CaIntroMark` 使用 `public/brand/ca-mark.svg` 的三个路径。网格沿原轮廓生成前后盖与连续侧壁，保留 CA 的凹形开口。CA 与道路使用同一深度缓冲，城市先以独立透明阶段绘制，侧板与牌面由组件和 CSS 展示。标识填色、厚度增长与摄像机运动同时启动，实体透明度和厚度取自同一填色进度。

摄像机从 C 左侧向上绕行，揭示平面标识的挤出厚度，再回正到 A 的开口前方进入道路。道路沿单个宽缓的水平弧线延展，相机提前看向弧线前方，终端显现前回到直线。道路、护栏、路牌与支架共用空间曲线，两端的位置、斜率和曲率连续。道路显现的边界由当前摄像机位置决定，不另设运动时序，也不压缩弯道几何。路牌与支架复用安装坐标和显现函数，牌面保持稳定朝向，标题来自现有双语资源，并标注真实路由或命令。

场景颜色、圆角与时长基础值取自共享 UI 的公开 token，门户维护场景几何和节奏倍率。道路采用倒角截面，护栏采用连续圆角扶手、通透栏板与细立柱，不生成内部重复端盖。路面分段光迹、路缘导光带和栏板刻线使用主题主辅色，流动进度取自现有摄像机位置。道路保留透光、柔光与边缘色，不独立实现实时背景模糊。WebGL 不可用或上下文丢失时保留 SVG 标识与终端入场。卸载时释放缓冲、程序、监听与逐帧任务。

道路外围分三层布置低面数楼宇剪影，采用阶梯状退台、分离的塔冠、斜屋顶和裙楼轮廓，照明由连续屋顶轮廓光和成组楼层灯带构成，留空道路、路牌及终端所在轴线。远景按距离雾化，底部融入背景。显现与终端接近时的淡出均由同一摄像机位置驱动。楼宇沿用场景深度缓冲与整体退场，不维护独立时钟。深浅色共用道路染色比例、材质细节和光效算法，导光纹路统一使用有色线迹混合，不按主题或背景亮度分支计算。配色取自共享主题变量，主题及系统配色变化刷新同一绘制实例。

城市三角形按摄像机方向稳定地从远到近排列，以固定的立面透明度绘制到离屏纹理，再将完整城市按摄像机进度整体合成到场景，之后恢复深度写入并绘制道路与 CA。淡入淡出只在合成阶段应用一次，避免逐个立面量化低透明度时累积亮度跳变。仅在观察方向变化时更新排序，不以透明度阈值丢弃建筑片元。远处立面细线与灯带随距离平滑减弱，避免不足一个像素的细节闪烁。城市纹理、帧缓冲、程序与顶点缓冲随场景卸载或上下文丢失一并释放，分配失败时沿用 SVG 回退。

城市淡入淡出回归位于 `tests/e2e/city-fade-continuity.spec.ts`：固定摄像机，以小步长改变低区间透明度，读取实际合成像素并检查亮度连续性。`tests/e2e/intro-fade.spec.ts` 同时检查绘制阶段、首屏背景连续性与跳过时的城市纹理释放。

道路终点后方的高层城市横跨远处视野，与近处两侧楼宇形成深度差。立面以竖向分格、楼层分缝和宽幅反射区区分体块，远处细节随雾化减弱。路面使用低幅颗粒、纵横接缝、粗糙度变化与路缘反射，细颗粒随距离衰减。纹理固定在场景坐标，不引入独立闪烁或运动。

道路采用高架标高，城市地面低于桥面。低层建筑与裙楼的屋顶位于桥面下方，中高层塔楼继续高于桥面。桥下横梁与桥墩延伸至城市地面，沿用道路曲线与显现进度。楼宇底部雾化以城市地面为基准，保留低处屋顶及下方立面的可见高度差。摄像机与终端投影继续使用桥面坐标。

栏杆立柱落在沿道路曲线连续延伸的边梁上。外侧路牌底座通过承托梁连接桥面边缘。路牌、底座与承托梁整体沿安装点平移，承托梁内端与桥体重叠，避免弯道处断开。连接件与主体共用材质、显现及退场进度。

边梁与承托梁的承载面位于路面下方，栏杆立柱与路牌底座延伸到同一承载标高。承托结构不与行车表面形成共面重叠，避免摄像机移动时产生深度冲突。几何回归同时检查表面分离与底座连接。

## 终端交接

穿梭末段按摄像机距离投影真实终端，可见性与透明度由同一条动画控制，使终端在日志开始前逐渐显现，再在终端可读后开始日志。归位从当前实际投影出发，位移与缩放保持连续，不在场景结束后另建交接实例。

真实终端显现前，目的地方向的两层入口光框逐渐出现，道路导向光迹同步增强。终端显现时光框与城市照明按摄像机距离渐退。光框只提供空间引导，不复制终端内容或会话。

空间退场由实际输出驱动：`boot.start` 开始日志并保留空间运动。`boot.content` 触发道路退场、页面显现与终端归位。`boot.ready` 等待归位完成后显示最后一行日志。日志完整播放后逐行输出欢迎字符画和文字，再启用正常命令输入。进度条表示阅读进度，不控制场景。

入场使用 WAAPI，这类变换不触发 CSS motion 事件。动画期间调用唯一共享 `glassRenderer.refresh()` 跟踪终端几何。变换延迟期不逐帧刷新。折射边缘仍由共享 Glass Runtime 绘制。

## 中断与验证

视口尺寸改变时结束入场并恢复正常布局。偏好变化、跳过和卸载取消同一组动画、异步任务与绘制。暂停与恢复不创建第二条时间线。

几何与网格单元测试位于终端 presentation。浏览器回归入口为 `tests/e2e/terminal-journey.spec.ts`、`terminal-intro-continuity.spec.ts`、`terminal-motion.spec.ts` 与 `hero-typewriter.spec.ts`。检查方式见 [工程质量规则](engineering-quality.md#分级与执行责任)，实际通过情况保存在带日期的审计记录中。自动化结果不等同最终视觉验收。
