# 文档写作规范（AI）

适用范围：空格与标点、用词两节及 [术语体系](terminology/README.md) 适用于全仓库 Markdown 与产品双语文案，含根 `AGENTS.md`、README 与 `.agents/` 过程材料。其余各节约束 `docs/**/*.md`。根 `AGENTS.md` 的强制约束继续有效，冲突时以根规则为准。本文件约束写法，不改变文档事实依据和职责划分。

## 目录结构

```text
docs/
  AGENTS.md                     本文件：全仓库行文规则与 docs 结构规范
  terminology/                  术语体系：对照表与翻译规则（入口 terminology/README.md）
  architecture/                 架构说明与现行接口，只描述当前真实情况
    engineering-quality.md      环境与依赖维护、门禁分级、代码与文档预算、CI 决策
    fonts.md                    字体角色、资源许可、加载与子集生成
    terminal-extending.md       终端命令、会话、外观与交互扩展接口
    home-intro.md               首页入场、场景绘制、终端交接与中断
    site-shell.md               站点导航、主题、语言控件与共享玻璃样式接入
```

过程材料（审计快照、实施计划）归 `.agents/notes/`，不进 `docs/`。新增专题文档先在本节登记条目和职责，再写作。

## 内容分工

| 内容 | 唯一维护处 |
| --- | --- |
| 全局约束与入口 | 根 `AGENTS.md` |
| 项目定位、主要技术、常用命令与贡献入口 | `README.md` |
| 环境准备、共享依赖、门禁分级、预算、CI 决策 | `docs/architecture/engineering-quality.md` |
| 终端现行接口 | `docs/architecture/terminal-extending.md` |
| 首页入场、场景绘制与终端交接 | `docs/architecture/home-intro.md` |
| 导航布局、主题与共享玻璃样式接入 | `docs/architecture/site-shell.md` |
| 字体角色、资产许可与子集生成 | `docs/architecture/fonts.md` |
| 术语、缩写与翻译规则 | `docs/terminology/` |
| 带日期的过程材料 | `.agents/notes/` |

一处事实一处维护，其他位置只链接不复制。README 面向项目用户，不承载 Agent 指令、本地开发路径、共享库同步、字体生成和页面实现清单。维护细节按上表维护，产品介绍不提前承诺未确定的功能。文档随对应能力进入提交。独立提交文档时，只描述该提交包含的事实。未采用的设计写入过程计划，采用后再同步现行接口。目录中的专题划分描述文档职责，不代表源码已经完成模块拆分。

## 写前

- 先确认事实依据：源码、配置、脚本输出优先于既有文档；不确认的内容不写成结论。
- 先查 [术语体系](terminology/README.md) 的对照表。未收录的条目先补表，再使用。一个概念只用一个词，不混用缩写、全称或中英文变体。
- 先确定该文档的单一职责；运行命令、CI 版本、正文内容等已有依据时只链接，不复制。

## 空格与标点

- 汉字与半角字母、数字、单位之间空一格：`Nuxt 4`、`3100 端口`、`1000 upem`、`GB2312 一级常用字`。
- 数字与 `%`、`°` 紧贴；版本号、路径、命令、代码标识符内部不插空格。
- 行内链接与左右文字之间空一格：`详见 [终端扩展接口](terminal-extending.md) 文档。` 链接紧邻标点、括号或行首行尾时不加空格：`见（[字体](#字体)）。`
- 行内代码、加粗、斜体只按中西文规则处理，不加额外空格：使用 `UiTerminalPrompt` 组件。
- 中文正文使用全角标点；全角标点前后不留半角空格；英文专名内部的点号、连字符保留。
- 分号只分隔紧密并列的分句。独立的意思用句号分开，不把多个独立句子串联成一句。中文注释按独立句断句，不沿用英文注释的分号。
- 中文引号用双引号“内容”和单引号‘内容’，不用「」或英文引号。
- 标题的 `#` 是 Markdown 语法：`#` 后恰好一个空格，不把 `#` 当作中西文间距的对象。
- 日期写 `2026-10-25`；时间写 `14:30`；区间写 `100–900`；数字一律半角。

## 用词

禁止比喻、营销和无法核实的模糊表达。能写对象、数量、条件或结果时，不写程度词。

| 不写 | 改写为 |
| --- | --- |
| 噪音 | 无关输出、重复信息、干扰内容（写明具体是哪一类） |
| 孤儿文档 | 无入口文档、未被引用的文档 |
| 赋能、抓手 | 支持、提供、入口、措施 |
| 闭环、收口 | 完整流程、收敛到确定状态、结束 |
| 落地、沉淀 | 实施、写入代码、记录、保存 |
| 打通、拉通 | 连接、统一 |
| 颗粒度、心智、体感 | 细化程度、认知、实际体验 |
| 强大、极致、无缝、丝滑、友好 | 具体能力、指标或操作结果 |
| 若干、大量、一些、等等 | 精确数量、完整枚举 |
| 值得注意的是、总而言之、综上所述 | 删除，直接写事实 |
| Review 者 | 审查者 |
| 最佳实践、生态 | 具体规则、依赖或工具链 |

- “对齐”只在能写出对齐对象和标准时使用，如“对齐 `TerminalAnchor`”；否则写“保持一致”。
- 写“边界”“契约”“形态”“体系”“权威”“叙事”“编排”“装配”“令牌”“事实来源”“内容归属”“共享材质”前先问能否点名具体对象：写“响应字段”“JSON 校验”“模块导出”“CA 标识”“动画”“创建并注入”“样式变量”“事实依据”“内容分工”“共享玻璃样式”，不写“响应形态”“校验边界”“权威标志”“叙事节奏”“空间编排”“装配服务”“共享令牌”“事实来源”“内容归属”“共享材质”；“契约”只用于前置条件、兼容承诺和不变量。
- 不写“我们”“你可以”等对话口吻；规范条文用祈使句或“必须/应当/可以”，事实用陈述句。
- 不写“未来可能”“大概”“或许”代替未知；未知就写“未验证”，并给出验证方式。
- 不用“首先/其次/最后”凑结构；段落按事实关系组织。
- 加粗与“必须”只留给改变行为的分句；处处强调等于没有重点。
- 英文词不接中文词缀：写“审查者”，不写 Review 者。有对应中文词时不用英文词充当词根。

## 结构

- 每篇一个一级标题；标题层级连续，不跳级；标题写主题，不写“概述”“其他”。
- 先结论后依据；段落一个主题；列表只放并列项，步骤用编号。
- 表格用于对比和映射；代码块标注语言；命令、路径、符号用行内代码。
- 仓库内链接用相对路径，外部链接用完整 URL；链接文字说明目标，不写“点击这里”。
- 不重复其他文档的规则和清单；用链接指向唯一维护处。
- 文档元数据用英文书写，正文保持中文：标题下一行以 `Status: adopted`、`Status: historical` 等值标注状态。历史文档标注 `Status: historical` 并给出替代文档，不机械删除有设计依据的记录。
- 计划、审计、验证快照写明日期，不写成长期规范。
- 正文不写“已实现”“即将支持”等状态标注；状态由源码、脚本和门禁承载，文档只描述当前事实。
- 现行事实不写日期和时间。带日期的观测、基线和验证记录归 `.agents/notes/`，docs 只描述当前状态。

## 格式与验证

- Markdown 由 Prettier 与 `prettier-plugin-markdown-compact-tables` 插件格式化：正文换行保留（`proseWrap: preserve`），表格单元格两侧各留一个空格，不对齐列宽。
- 文件使用 UTF-8、LF、末尾换行；空行分隔标题、段落、列表、代码块和表格。
- 写完运行 `bun run format:check`、`bun run check:docs` 与 `bun run check:budgets`。链接目标由 `check:docs` 机械校验，术语一致性仍需人工核对。
- 单个子目录 `AGENTS.md` 应当不超过 100 行，硬上限 120 行；超限先拆分职责，不调高阈值。
