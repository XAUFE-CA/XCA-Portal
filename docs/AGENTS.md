# 文档写作规范

适用范围：全仓库 Markdown。根 [AGENTS.md](../AGENTS.md) 的修改与 Git 约束继续有效。

## 目录结构

```text
docs/
  AGENTS.md               本文件：职责、行文与验证
  architecture/
    engineering-quality.md  共享依赖、门禁、预算与验证责任
  terminology/
    README.md             术语入口与维护方式
    terms.md              品牌与缩写对照
```

根文件 README 负责面向用户的项目介绍与基本开发入口。专题文档只在对应能力进入仓库时新增，并在本节登记职责；不创建空模板。

## 内容归属

- 全局协作和修改约束只维护在根 `AGENTS.md`。
- 项目定位、主要技术、基本开发命令与贡献入口只维护在根 README。
- 工具、共享依赖、门禁、预算与验证责任只维护在 [工程质量契约](architecture/engineering-quality.md)。
- 品牌与缩写解释只维护在 [术语表](terminology/terms.md)。
- 文档只描述当前提交包含的事实。提议与采用后的接口分别维护，不能把计划写成当前能力。

一处事实一处维护，其他位置链接引用。README 面向项目用户，不承载 Agent 指令、本地开发路径、共享库同步、字体生成和页面实现清单。维护细节归对应工程文档，产品介绍不提前承诺未确定的功能。事实优先查源码、配置与实际检查结果。

## 行文

- 每篇一个一级标题，标题层级连续，段落只表达一个主题。
- 汉字与半角字母、数字之间空一格，路径、命令和代码标识符内部不插空格。
- 中文正文使用全角标点；链接紧邻标点时不加空格，其他情况按中西文间距处理。
- 日期写 `YYYY-MM-DD`，数字使用半角。
- 路径、命令与代码标识符用行内代码，代码块标注语言。
- 仓库内链接使用相对路径，外部链接使用完整 URL，链接文字说明目标。
- 使用可核实的对象、条件和结果，不写模糊宣传、不重复其他文档的规范。
- 规范使用陈述句或祈使句，正文不用对话口吻。术语解释只放在术语表。

## 格式与验证

文件使用 UTF-8、LF、末尾换行，标题、段落、列表和表格之间留空行。Markdown 使用 Prettier，写完运行 `bun run format:check`、`bun run check:docs` 与 `bun run check:budgets`，代码改动运行 `bun run check`。格式和 Lint 分别记录结果，工具职责见工程质量契约。

检查全部内部链接及片段目标，并人工核对正文提到的命令、路径和能力是否在候选提交中存在。没有进入候选提交的文件不能补足链接目标；工作区中存在不代表提交中存在。
